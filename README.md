# DG-LAB 2.0 / 3.0 Web 控制器

这是一个基于 ESP32 的 Web 控制器项目。ESP32 作为 BLE 客户端连接 DG-LAB 2.0 / 3.0 脉冲主机，并通过本地 Wi-Fi Web 页面控制双通道强度和波形。协议实现以仓库内 `docs/coyote` 官方协议文档和 `docs/Web Bluetooth` 官方演示为准。

---

## 项目功能

- **设备扫描与连接**：按官方演示的名称前缀发现设备；2.0 匹配 `D-LAB`，3.0 匹配 `47`，不会硬编码某一台设备的完整名称。
- **波形控制**：选择并发送预定义的波形到设备的 A/B 通道。
- **强度调整**：支持 A/B 通道相对增加、相对减少和绝对设置。
- **强度反馈**：2.0 订阅 `1504` 强度通知；3.0 使用 B1 序列反馈，并在反馈超时时标记为未确认。

断线恢复：意外断开时会保留发送意图，并仅在重新连接到相同 BLE 地址及地址类型的设备后恢复波形。手动断开或手动选择另一台设备时，发送状态保持停止，需要在界面中重新点击“开始发送”。

### 协议行为

- DG-LAB 2.0 使用 `180B` 服务：`1504` 读/写/通知强度，`1505` / `1506` 写入 B/A 通道三字节波形。
- DG-LAB 3.0 使用 `180C` 服务：每 100 ms 只发送一条 20 字节 B0，同时携带强度命令和 A/B 两个八字节波形块；相对命令在线路上发送变化量，绝对命令发送目标值。
- DG-LAB 3.0 的强度命令使用 `1..15` 序列号并等待匹配 B1；等待期间的新请求会合并排队，不会伪装成已发送。连接或重连后都会重新写入 BF 配置。项目当前使用 A/B 软上限 `200/200`、频率平衡 `128/0`、强度平衡 `128/0`。
- 停止输出时仍可通过周期 B0 修改 3.0 强度，但两个通道都使用官方规则定义的禁用波形块，不产生波形输出。

### 代码结构

- `lib/DgLabControl`：不依赖 Arduino/BLE 的协议编码、强度状态机、周期组帧和同设备恢复策略。
- `src/BleManager.*`：扫描、profile 建立、通知事件和 BLE client 生命周期。
- `src/OutputController.*`：V2/V3 输出调度、强度请求和连接恢复协调。
- `src/WebUi.*`：HTTP 路由和页面渲染。
- `src/Waveforms.*`：与官方演示一致的内置波形表。
- `src/AppState.*`、`src/AppLog.*`：应用状态和固定容量日志。
- `src/main.cpp`：初始化及主循环编排。

## 默认 Wi-Fi 热点信息

在设备启动后，ESP32 会创建一个名为 `ESP32-Controller` 的 Wi-Fi 热点，默认密码为 `12345678`。该热点的 SSID 默认为隐藏状态，需在终端设备上手动输入网络名称进行连接。连接成功后打开浏览器，访问 `http://192.168.4.1/` 即可进入控制界面。

## 使用说明

### 硬件要求

- ESP32开发板
- 郊狼主机
- 用来连接脉冲主机的蓝牙设备

### 软件要求

- [PlatformIO](https://platformio.org/) 环境（PlatformIO IDE 或 PlatformIO Core）。

### 安装步骤

1. 下载或克隆本项目代码。
2. 使用 PlatformIO 打开项目根目录。
3. 连接 ESP32 开发板，构建并上传固件：

   ```bash
   pio run
   pio run --target upload
   ```

4. 如需查看串口日志，运行：

   ```bash
   pio device monitor
   ```

5. 上传完成后，ESP32 会启动并创建一个名为 `ESP32-Controller` 的 Wi-Fi 隐藏热点。
6. 在终端设备上手动添加并连接该 Wi-Fi 热点。在浏览器中访问 `http://192.168.4.1/`，即可进入控制界面。

> 固件包含 Web 与 BLE 功能，体积超过默认应用分区。项目已使用 `huge_app.csv`（3 MB 应用区）分区方案，因此不支持 OTA 双分区升级。

### 测试

纯协议和状态机测试使用 PlatformIO Native 环境：

```bash
pio test -e native
pio run -e esp32dev
```

GitHub Actions 会依次运行 Native 测试和 ESP32 固件构建。本机运行 Native 测试需要系统中可用的 `gcc` / `g++`。

## 注意事项

- 2.0 profile 已按官方文档实现，但仍建议在真实硬件上验证强度通知、持续波形和断线重连。
- Web 页面显示“未确认”时，数值是待设备反馈的预测值；请以设备实际状态为准。
